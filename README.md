# AI Phone Auditor — исходный проект 1.0.0

Локальный Android-аудитор на Kotlin. Работа на телефоне без root, ADB, компьютера, сетевых разрешений и API-ключа. Анализ выполняется объяснимыми правилами; встроенной нейросети или антивирусной базы нет. Для отдельного ИИ-анализа пользователь вручную передает отчет.

## Фактический статус поставки

**APK не собран и не приложен.** В среде подготовки отсутствовал Android SDK; загрузка инструментов сборки была недоступна. Нельзя считать этот проект проверенным на Android-устройстве или готовым релизом.

Фактически выполнены компиляция платформонезависимой части Kotlin, 30 проверок логики и редактирования экспорта и независимый разбор созданного JSON средствами Python. Android-модули, manifest merger, Android Lint, упаковка APK, подпись и установка на смартфон здесь не проверялись. Настроенный workflow должен выполнить сборку и проверки в GitHub Actions; успешный запуск CI пока не подтвержден.

Установить ZIP как приложение нельзя. Для получения APK используй `docs/PHONE-BUILD.md`. Пользователю не нужен компьютер, но сборка происходит на сервере GitHub, а не локально на процессоре телефона. Нужны аккаунт GitHub, доступ к Actions и интернет на этапе сборки. Отчеты телефона в GitHub не передаются.

## Реализованные модули

* Обзор: модель, Android/API, патч безопасности, архитектуры, ядра, доступные процессу, общий и доступный объем RAM, состояние нехватки RAM и раздела данных.
* Батарея: заряд, температура батареи, напряжение, доступные ток/счетчик оставшегося заряда, статус контроллера, тепловой статус Android. Наблюдение раз в 30 секунд только при открытом приложении; до 120 точек. При сворачивании, блокировке или повороте останавливается.
* Приложения: пакет, имя, версии, даты, источник установки, системный флаг, список разрешений и флаги PackageManager. Декларация специального разрешения не подменяется выданным доступом.
* Доступные специальные полномочия: включенные службы Accessibility, слушатели уведомлений и администраторы текущего профиля; при отказе Android — неизвестно. Проверяются исключения оптимизации батареи.
* Дополнительный доступ Usage Access: агрегаты использования и foreground services, размеры на накопителе, счетчики Wi-Fi/мобильного трафика по UID. Производитель может ограничить отдельные показатели. Запрашиваются последние 7 дней; фактические границы корзин UsageStats сохраняются.
* Поиск, фильтр системных пакетов и сортировки списка, карточка всех разрешений, объяснения сигналов, переходы в штатные настройки.
* История до 10 проверок / целевой предел 30 МиБ, текущий отчет сохраняется даже если он один превышает лимит. Встроенное удаление истории и подготовленных файлов.
* JSON и TXT, предпросмотр, пользовательский выбор включения списка приложений, использования и сети, Android Sharesheet и Storage Access Framework.

## Не реализовано и не заявляется

Точное энергопотребление/CPU/RAM других UID; перехват сети, DNS и TLS; сигнатурная проверка APK на вредоносность; обход песочницы; поиск всех видов шпионского ПО; точный износ батареи; полная история автозапуска; фоновый постоянный мониторинг; автоматические «ускорители» и очистка. Локальный VPN не создается.

В частности, время использования не переводится в проценты батареи. `RECEIVE_BOOT_COMPLETED` — только декларация разрешения. `StorageStats.cacheBytes` входит в `dataBytes`: суммируется `appBytes + dataBytes`, без повторного добавления кэша. Общий UID явно отмечается; счетчики нельзя повторно складывать по пакетам. `GOOD` у батареи не означает нулевой износ. Отсутствие результатов не является вердиктом «телефон безопасен».

## Приватность

В manifest всего три разрешения:

- `QUERY_ALL_PACKAGES` — основной сценарий аудита установленного ПО текущего профиля; это не подтверждение допуска приложения в Google Play.
- `PACKAGE_USAGE_STATS` — необязательный доступ, включается вручную через системные настройки.
- `ACCESS_NETWORK_STATE` — системный тип соединения.

Нет `INTERNET`, доступа к фотографиям, внешнему хранилищу, SMS, контактам, аккаунтам, камере, микрофону или геолокации. Нет собственной Accessibility-службы, администратора устройства, фонового сервиса, ресивера автозагрузки, рекламы и аналитики. В списке проверяемых разрешений эти названия могут встречаться как данные **других** приложений.

Отчеты хранятся во внутреннем каталоге приложения; backup/device transfer исключены правилами. Временные экспорты находятся в cache, provider не экспортирован и открывает только допустимые файлы по временным URI-разрешениям, только для чтения. Подготовленные экспорты ограничены количеством и удаляются по возрасту при следующем экспорте; нет обещания удаления строго через 24 часа. При очистке истории удаляются и staged-файлы. Уже переданные или сохраненные во внешнем месте копии пользователь удаляет отдельно.

Время использования и сеть по умолчанию не включаются в экспорт. Исключение категории удаляет также производные выводы. Исключение списка приложений удаляет связанные идентификаторы и подробности ошибок. Список программ сам по себе может быть чувствительным — перед отправкой посмотри отчет.

## Архитектура и версии

- Kotlin 2.2.21, Android Gradle Plugin 8.11.1, Gradle 8.13, JDK 17.
- `minSdk 31` (Android 12), `compileSdk/targetSdk 35`, Build Tools 35.0.0.
- Android 12–16 — целевой диапазон проверки; реальная совместимость с Samsung S21 Ultra и иными моделями пока не подтверждена.
- Нативные Android Views с темной темой: без WebView, Compose, Room и WorkManager. Зависимости времени выполнения — стандартная библиотека Kotlin и API Android. Это более узкая реализация, чем ранее обсуждавшийся максимальный мастер-промпт.
- `core/Models.kt`: типизированные записи, статус доступности, схема 1.0.0.
- `core/RiskEngine.kt`: локальные объяснимые правила, не вероятности заражения.
- `core/JsonCodec.kt`: JSON writer, приватность/редакция, форматирование.
- `platform/AndroidCollectors.kt`: публичные Android API и обработка недоступности.
- `platform/ReportFiles.kt`: история, JSON parser Android, экспорт и read-only provider.
- `AuditorApplication.kt`: состояние приложения, один рабочий executor, отмена, уведомление UI.
- `ui/MainActivity.kt`: шесть экранов, детали, разрешения, график, ручной экспорт.

Сканирование работает вне UI-потока; состояние переживает поворот через Application. После гибели процесса текущая модель не восстанавливается автоматически, но сохраненные отчеты доступны в истории. Список программ может измениться во время сканирования; пропуски отмечаются в покрытии. Блокирующий запрос Android не прерывается мгновенно: отмена проверяется между запросами.

## Проверки и сборка

Быстрые тесты ядра без SDK, при наличии Kotlin/JDK/Python:

```sh
bash tools/test-core.sh
```

Сборка с установленными Android SDK и Gradle 8.13:

```sh
bash tools/build.sh
```

В комплекте нет бинарного Gradle Wrapper. Workflow устанавливает конкретную версию Gradle через официальный Gradle action и вызывает `gradle`. Это не мешает облачной сборке. Для стороннего IDE-процесса установи Gradle 8.13 либо создай стандартный wrapper в своей среде.

CI запускает JUnit, Lint, `assembleDebug`, проверяет подпись `apksigner`, отсутствие INTERNET в итоговом manifest и публикует APK, контрольную сумму и отчет подписи. Debug APK предназначен для личной проверки, не для публикации. У разных чистых запусков ключ debug-подписи может отличаться: установка поверх прежней версии может не пройти. Не удаляй старую установку, пока не сохранил нужные отчеты. Для регулярных обновлений настрой собственный стабильный ключ релиза и секреты CI; ключи в исходниках отсутствуют.

До использования как надежного инструмента пройди `docs/ACCEPTANCE.md`. Все ссылки на документацию — в `docs/SOURCES.md`.
