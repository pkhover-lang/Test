# Как получить APK, пользуясь только телефоном

**Сейчас предоставлены исходники, а не установочный APK. Сборка еще не была выполнена.**

Диагностика будет локальной. Следующий способ использует телефон для управления сборкой в облаке GitHub. Это не компиляция непосредственно на телефоне. Нужны учетная запись GitHub и разрешенные Actions; их доступность и квоты зависят от аккаунта. Никакие диагностические отчеты загружать в репозиторий не нужно.

## 1. Сохрани файлы из ответа

Сохрани `AI-Phone-Auditor-source.zip` без переименования. Извлекать исходники на телефоне не требуется. Второй файл `Build-APK-workflow.yml` содержит сценарий сборки, который нужно поместить по специальному пути.

## 2. Создай репозиторий

Открой GitHub в браузере и войди в аккаунт. Создай новый репозиторий, например `ai-phone-auditor`, лучше **Private**. Добавь README при создании, чтобы сразу появилась ветка и кнопка Add file. При необходимости включи в браузере «Версия для ПК» — сам компьютер не нужен.

## 3. Загрузи ZIP в корень

Выбери **Add file → Upload files → Choose your files**, выбери `AI-Phone-Auditor-source.zip`, затем **Commit changes**. ZIP должен лежать прямо в корне, а не в подпапке и не внутри другого ZIP.

## 4. Добавь workflow

Выбери **Add file → Create new file**. Имя нового файла введи целиком:

```
.github/workflows/build-apk.yml
```

Вставь в редактор полное содержимое приложенного `Build-APK-workflow.yml` (либо одноименного `.txt`). Сохрани через **Commit changes**. Важно: загрузить YAML просто в корень недостаточно — GitHub запускает workflow именно из `.github/workflows/`.

## 5. Запусти сборку

Открой вкладку **Actions → Build APK**. Добавление workflow должно запустить сборку; при необходимости нажми **Run workflow**. Когда оба файла уже добавлены, повторный запуск использует их вместе. Если Actions отключены, потребуется разрешить их в настройках своего репозитория.

Сценарий распакует ZIP на сервере, подготовит JDK/Gradle/SDK, запустит тесты и Lint, соберет debug APK и проверит его подпись. **Зеленый статус означает успешное выполнение workflow, но не тестирование на твоем телефоне.** При красном статусе APK не считается собранным: открой упавший шаг и сохрани текст ошибки или артефакт Build-reports. Не отключай проверку ошибок ради зеленой галочки.

## 6. Получи APK

Внизу успешно завершенного запуска найди **Artifacts → AI-Phone-Auditor-APK**. Скачай и распакуй архив. Внутри будут:

- `AI-Phone-Auditor-1.0.0-debug.apk`;
- `SHA256SUMS.txt`;
- `signature.txt` и `permissions.txt`.

Артефакты в этом workflow хранятся 7 дней. Для скачивания нужно быть авторизованным и иметь доступ к репозиторию.

## 7. Установка и первая проверка

Открой APK на телефоне. Установка вне магазина может потребовать отдельного разрешения для браузера или файлового менеджера. Это не разрешение, которое требуется самому аудитору для работы. Не отключай Play Protect и не обходи предупреждение, называющее конкретную угрозу; сначала проверь причину. Сборка новая и не имеет репутации публичного приложения.

Открой AI Phone Auditor → **Начать диагностику**. Сначала проверь базовый режим. Для расширенных показателей используй **Действия → Разрешить или отозвать статистику** и включи доступ только для AI Phone Auditor. Вернись и повтори диагностику.

Не предоставляй самому аудитору Accessibility, администратора, VPN, доступ к SMS, контактам, фото или геолокации: он их не запрашивает.

В разделе **Отчет** выбери состав данных, посмотри предпросмотр и сохрани JSON/TXT. Прикрепи файл в нужный чат вручную. Включение времени использования и сети полезно для анализа активности, но раскрывает больше метаданных.

## Обновления

Debug-ключ может различаться между чистыми CI-запусками, поэтому обновление поверх предыдущего APK может быть отклонено Android. Сначала экспортируй нужную историю; удаление приложения удаляет его внутренние данные. Для постоянных обновлений нужен стабильный личный ключ подписи, не опубликованный в репозитории.

Подробная техническая документация и ссылки: `README.md`, `SOURCES.md`, `ACCEPTANCE.md`.
